# プロジェクト切り替え（Issue #197）

## 配置と操作範囲

Web 単体版は `CREC_Web.exe`（DLL 実行時は DLL）の隣の `Projects`、デスクトップ版は `web/Projects` 以下から `.crec` を探します。起動時に指定した既存のプロジェクトがこの範囲外でも、切り替え先は必ずこの範囲内です。

`.crec` の `projectSettings.projectLocation` は `.crec` があるディレクトリを基準に解決します。絶対パスも範囲内なら利用できます。データフォルダも `Projects` 内に置いてください。リンク、ジャンクション、範囲外参照は選択できません。データフォルダの子孫にあるリンクも拒否します。`Projects` は静的ファイルとして配信されません。

認証・権限制御は別 Issue で実装する方針とし、今回の変更には含めません。管理画面の「プロジェクトを開く」から、ログインなしで候補の一覧・切り替えを利用できます。サーバーへアクセスできる利用者は誰でも切り替え可能です。Issue #197 の管理者限定操作に関する要件は、認証機能の実装時に対応します。

デスクトップ版では、プロジェクトのパスと名前を同じ OS ユーザーのみが利用できる名前付きパイプでホストに通知し、タイトルと現在のパスを同期します。公開設定変更による再起動では、サーバー停止後の最終通知を受け取ってからそのプロジェクトを再び開きます。

## API

| API | 説明 |
| --- | --- |
| `GET /api/projects/status` | 現在の `revision` と `name`。パスは返しません。 |
| `GET /api/projects` | 候補一覧。`id`, `name`, `location`, `isCurrent`, `errorCode`。 |
| `POST /api/projects/switch` | `{ "id": "一覧のID", "revision": "操作元のrevision" }` で切り替えます。 |

管理 API の更新要求は `X-CREC-Request: 1` が必要です。外部 Origin と外部サイトからの要求は、既存 API の CORS 設定にかかわらず拒否します。この処理は外部サイトからの不意な操作を防ぐためのもので、利用者の認証や権限制御を行うものではありません。

既存の API を含むすべての更新要求には、画面やクライアントが読み込んだ時点の `revision` を `X-CREC-Project` ヘッダーで付けます。読み取り要求にも付けると古いプロジェクトからの読み取りを拒否できます。動画やダウンロードの URL では `projectRevision` クエリを使えます。古い・未指定の revision による更新は409、切り替え待機中の新規要求は503です。切り替え中に受け付けられなかった更新を、新しい revision で自動再送してはいけません。

切り替え処理は実行中のリクエスト（保存、アップロード、ファイル送信を含む）の完了を待ちます。その後に候補を再検証し、設定とキャッシュを切り替えます。失敗時は現在のプロジェクトを維持します。ポート・公開範囲は変更しません。

未保存入力の破棄確認は、プロジェクト切り替えと、他の画面での切り替え通知から再読み込みする際に行います。通常のページ移動・再読み込み・タブ終了には確認を追加しません。保存済みの編集欄や、閉じて破棄したモーダルは確認対象から外し、別の編集欄の未保存入力は保持します。

## 新規作成機能との共通処理

Issue #196 は同じ `Projects` へプロジェクトとデータを保存し、`ProjectCatalogService` が返す識別子を `ProjectRuntime.SwitchAsync` に渡すことで共通の検証・切り替え処理を利用できます。呼び出し元が通常のリクエストリースを保持したまま `SwitchAsync` を待つと自分自身の完了待ちになるため、作成エンドポイントからは保存完了後に別の切り替え要求を行ってください。

## アプリケーションの更新

更新ツールの新設は別 Issue の範囲とします。手動更新では、アプリケーションを停止し、Web 単体版の `Projects` またはデスクトップ版の `web/Projects` をバックアップしてください。新しい配布物を別のフォルダへ展開し、これらのユーザーデータフォルダを除いてアプリケーションのファイルを上書きします。`Projects` の削除・上書き、インストール先全体の削除、ミラー同期による更新は行わないでください。

ビルド・発行の入力にもユーザーデータを含めず、Web のビルド出力からデスクトップへコピーするときも `Projects` を除外します。

## 回帰テスト

`dotnet run --project tests/ProjectSwitching.Tests` で探索、検証、A→B→A、キャッシュ破棄、排他制御、失敗時維持、更新の世代確認、認証なしでの一覧・切り替え、外部 Origin 拒否を実行します。HTTP の統合テストと、デスクトップホストが起動する実際の子プロセスを使った IPC・再起動のテストも含みます。後者には ASP.NET Core の開発用 HTTPS 証明書が必要です。テスト用データは一時ディレクトリおよびテスト出力の `web/Projects/host-tests-*` に作成して削除します。

`node tests/project-session.test.cjs` は古い画面の通信拒否、破棄確認のキャンセル、世代付きメディア URL、3言語の翻訳キーを検証します。
