# プロジェクト切り替え（Issue #197）

## 配置と操作範囲

ブラウザーのプロジェクト一覧は、Web 単体版では `CREC_Web.exe`（DLL 実行時は DLL）の隣の `Projects`、デスクトップ版のサーバーへ接続した場合は `web/Projects` 以下から `.crec` を探します。起動時に指定した既存のプロジェクトファイルがこの範囲外でも、一覧からの切り替え先の `.crec` ファイルは必ずこの範囲内です。実データの保存場所は `Projects` 内に制限しません。

「プロジェクトを開く」は Web 画面に一本化しています。デスクトップ内の WebView では Windows のファイル選択ダイアログを開き、任意の場所にある `.crec` を指定できます。選択前に未保存入力の破棄を確認し、選択後は既存のサーバー再起動処理で開きます。キャンセル時は現在の画面を維持します。通常のブラウザーでは従来の候補一覧を開きます。デスクトップでネットワーク公開した場合も、外部のブラウザーにはファイル選択機能を提供しません。

`.crec` の `projectSettings.projectLocation` は既存の仕様を維持し、相対パスなら Web サーバープロセスの作業ディレクトリを基準に解決します。`.crec` の所在ディレクトリが基準になるわけではありません。起動・設定保存・切り替えで同じ規則を使い、ファイル内のパス表記は変更しません。デスクトップ版の作業ディレクトリは `web` です。Web 単体版では再起動時も同じ作業ディレクトリを使ってください。別ドライブを含む絶対パスも利用できます。例えば `Projects/撮影機材.crec` から `S:\CREC\撮影機材` の実データを参照できます。

データフォルダは、サーバーを実行するユーザーがアクセスできる必要があります。一覧からの切り替え時には所在・アクセス可否を再検証し、失敗時は元のプロジェクトを維持します。ブラウザから実データのパスを直接指定することはできません。一覧 API では、`Projects` 外の `.crec` や一覧外の識別子を引き続き拒否します。プロジェクトファイル・データフォルダまでの経路と、データフォルダの子孫にあるリンク・ジャンクションも拒否します。`Projects` は静的ファイルとして配信されません。

起動時の `--project`、標準入力、デスクトップ版のファイル指定は引き続き利用できます。Web 単体版の対話起動では、プロジェクトパスの入力を Enter で省略すると未選択状態で起動します。非対話起動では `--project` を省略できます（例：`CREC_Web --port 5000 --local-only --non-interactive`）。デスクトップ版も `.crec` を指定せずに起動できます。未選択の場合はホーム画面のプロジェクト選択を開きます。ポート・公開範囲の指定方法は従来どおりです。明示的に指定された `.crec` の読み込み・必須設定の取得に失敗した場合は、起動を中止します。

未選択でも世代を発行し、候補一覧・状態確認・切り替えを利用できます。データ操作 API は `409 projects-not-selected` で拒否し、作業ディレクトリをプロジェクトデータとして使用しません。候補がない場合も、選択画面に理由を表示し、一覧を再読み込みできます。選択に成功すると世代を更新して通常のホーム画面へ移動します。失敗した場合は未選択状態を維持します。デスクトップ版は未選択でも起動確認・公開設定変更による再起動が可能です。

認証・権限制御は別 Issue で実装する方針とし、今回の変更には含めません。管理画面の「プロジェクトを開く」から、ログインなしで候補の一覧・切り替えを利用できます。サーバーへアクセスできる利用者は誰でも切り替え可能です。Issue #197 の管理者限定操作に関する要件は、認証機能の実装時に対応します。

デスクトップ版では、プロジェクトのパスと名前を同じ OS ユーザーのみが利用できる名前付きパイプでホストに通知し、タイトルと現在のパスを同期します。公開設定変更による再起動では、サーバー停止後の最終通知を受け取ってからそのプロジェクトを再び開きます。

## API

| API | 説明 |
| --- | --- |
| `GET /api/projects/status` | 現在の `revision` と `name`。未選択なら `name` は null。パスは返しません。 |
| `GET /api/projects` | 候補一覧。`id`, `name`, `location`, `isCurrent`, `errorCode`。 |
| `POST /api/projects/switch` | `{ "id": "一覧のID", "revision": "操作元のrevision" }` で切り替えます。 |

管理 API の更新要求は `X-CREC-Request: 1` が必要です。外部 Origin と外部サイトからの要求は、既存 API の CORS 設定にかかわらず拒否します。この処理は外部サイトからの不意な操作を防ぐためのもので、利用者の認証や権限制御を行うものではありません。

既存の API を含むすべての更新要求には、画面やクライアントが読み込んだ時点の `revision` を `X-CREC-Project` ヘッダーで付けます。読み取り要求にも付けると古いプロジェクトからの読み取りを拒否できます。動画やダウンロードの URL では `projectRevision` クエリを使えます。古い・未指定の revision による更新は409、切り替え待機中の新規要求は503です。切り替え中に受け付けられなかった更新を、新しい revision で自動再送してはいけません。

一覧取得時に、候補の識別子と相対パスの対応をサーバー側に保持します。切り替え処理は実行中のリクエスト（保存、アップロード、ファイル送信を含む）の完了を待ち、その対応から選択先を特定して、選択先の `.crec` とデータフォルダだけを再検証します。他の候補の再走査や検証結果の使い回しは行いません。設定とキャッシュを切り替え、失敗時は現在のプロジェクトを維持します。ポート・公開範囲は変更しません。

未保存入力の破棄確認は、プロジェクト切り替えと、他の画面での切り替え通知から再読み込みする際に行います。通常のページ移動・再読み込み・タブ終了には確認を追加しません。保存済みの編集欄や、閉じて破棄したモーダルは確認対象から外し、別の編集欄の未保存入力は保持します。

## 新規作成機能との共通処理

Issue #196 は同じ `Projects` へ `.crec` ファイルを保存し、`ProjectCatalogService` が返す識別子を `ProjectRuntime.SwitchAsync` に渡すことで共通の検証・切り替え処理を利用できます。実データの保存先は `.crec` の `projectLocation` で指定します。呼び出し元が通常のリクエストリースを保持したまま `SwitchAsync` を待つと自分自身の完了待ちになるため、作成エンドポイントからは保存完了後に別の切り替え要求を行ってください。

## アプリケーションの更新

更新ツールの新設は別 Issue の範囲とします。手動更新では、アプリケーションを停止し、Web 単体版の `Projects` またはデスクトップ版の `web/Projects` をバックアップしてください。新しい配布物を別のフォルダへ展開し、これらのユーザーデータフォルダを除いてアプリケーションのファイルを上書きします。`Projects` の削除・上書き、インストール先全体の削除、ミラー同期による更新は行わないでください。

ビルド・発行の入力にもユーザーデータを含めず、Web のビルド出力からデスクトップへコピーするときも `Projects` を除外します。
